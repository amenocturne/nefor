# Nefor MAG in Five Minutes

This guide assumes [MAG in Five Minutes](<../01. core/00. MAG in Five Minutes.md>).
MAG supplies typed immutable data, ordinary functions, nominal algebraic data
types, and one artifact value. Nefor's libraries use those mechanisms to build
nodes, agents, deterministic commands, worktrees, products, fixed parallel
work, and runtime-sized consumers. None introduces graph-specific syntax.

> **Scope:** This guide teaches MAG and Nefor library composition only; prompts,
> task decomposition, review policy, permissions, and domain practice are
> intentionally simplified and are not prescriptions.

The smallest complete program selects the facade names it uses, constructs one
root-capable node, and closes it directly:

```mag
import nefor.{ShellScriptParams, Timeout, compile_graph, script}

compile_graph(script("hello", ShellScriptParams {
  script: "printf 'hello\\n'",
  cwd: ".",
  timeout: named(Timeout, Seconds, 30),
}))
```

`script(...)` has type `Node<Unit, ProcessResult>`. Constructing it runs
nothing; `compile_graph` adds the output boundary, validates the graph, and
returns its immutable artifact. At runtime an exposed, unfed `Unit` input gets
one activation, while a fed node waits for its dependency.

The next program grows that root into a typed development workflow, then adds
runtime-sized follow-up work. Its imports keep the public authoring surface
visible: application code selects short names from the `nefor` facade,
configuration-owned agents stay qualified, and only `Either` and `Result` come
from their defining core module. Protocol internals remain behind the facade.

```mag
import agents.{}
import core.types.{Either, Result}
import nefor.{&&&, *>, >>>, AgentError, CreateSpec, DynamicList, Node, ProcessResult, ProviderInput, ShellScriptParams, Timeout, ToolApprovalPolicy, ToolApprovalRules, Worktree, and_then, before, choose, compile_graph, context, create, general_tools, identity, lift, map_error, node_named, result_map, script, sequence, source, traverse}

// Agents speak in application types rather than generic task or text records.
type DevelopmentTask {prompt: String}
newtype LineNumber = Int
type ReviewComment {path: String, line: LineNumber, body: String}
type Review {summary: String, comments: List<ReviewComment>}
type Implementation {summary: String}
type Approved {review: Review}
type NeedChanges {review: Review}
type Followup {title: String, instructions: String}
type Finding {title: String, finding: String}
type FinalSummary {summary: String}

type DevelopmentConfig {
  repository: String,
  worktree: String,
  branch: String,
  base: String,
  build: String
}

// Default selects the runtime's configured tool-approval behavior. Rules takes
// a ToolApprovalRules payload for mechanism-neutral per-agent metadata. The
// current gate does not enforce those rules, so a "deny" entry is not itself
// an execution barrier.
let reviewer_config = agents.AgentConfig {
  model: agents.standard,
  system: "Review the task and return concrete ReviewComment values with repository-relative path, source line, and actionable body.",
  tools: general_tools,
  tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
  max_corrections: 2
}

// IDs are opaque actor identities; reusable behavior stays in config. Mapping
// one config over IDs produces same-shaped nodes, and sequence sends one shared
// DevelopmentTask to every node and returns results in ID-list order.
let review_ids = ["security-review", "test-review"]
let review_nodes = map(
  ((|id| => agents.agent<DevelopmentTask, Review>(id, reviewer_config)): fn(String) -> Node<DevelopmentTask, Result<AgentError, Review>>),
  review_ids,
)
let parallel_reviews = sequence(review_nodes)

// A reusable workflow is an ordinary function returning one Node boundary.
// The primitive id is separate from repository-specific reusable config.
let development_workflow: fn(String, DevelopmentConfig) -> Node<DevelopmentTask, Result<AgentError, Review>> = |id, config| => {
  let task = identity<DevelopmentTask>(str(id, ".task"))

  let worktree = create(str(id, ".worktree"), CreateSpec {
    repository: get(config, "repository"),
    path: get(config, "worktree"),
    branch: get(config, "branch"),
    base: get(config, "base")
  })
  let worktree_after_task = identity<DevelopmentTask>(str(id, ".worktree-trigger")) *> worktree
  let implementation_input: Node<DevelopmentTask, (DevelopmentTask, Worktree)> = task &&& worktree_after_task

  let implementer = agents.agent<(DevelopmentTask, Worktree), Implementation>(str(id, ".implementer"), agents.AgentConfig {
    model: agents.standard,
    system: "Implement the task in its worktree.",
    tools: general_tools,
    tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
    max_corrections: 2
  })
  let implemented: Node<DevelopmentTask, Result<AgentError, Implementation>> = implementation_input >>> implementer

  // Pair each successful implementation with its bounded deterministic build.
  let build = script(str(id, ".build"), ShellScriptParams {
    script: get(config, "build"),
    cwd: get(config, "worktree"),
    timeout: named(Timeout, Minutes, 2)
  })
  let implementation = identity<Implementation>(str(id, ".implementation"))
  let build_after_implementation = identity<Implementation>(str(id, ".build-trigger")) *> build
  let implementation_and_build = implementation &&& build_after_implementation
  let built: Node<DevelopmentTask, Result<AgentError, (Implementation, ProcessResult)>> = result_map(implemented, implementation_and_build)

  let reviewer = agents.agent<(DevelopmentTask, Result<AgentError, (Implementation, ProcessResult)>), Review>(str(id, ".reviewer"), reviewer_config)

  // identity preserves original intent; &&& sends the same task through both
  // branches; the product emits only after both results exist.
  let retained_task = identity<DevelopmentTask>(str(id, ".retained-task"))
  let review_input = retained_task &&& built
  let review_result = review_input >>> reviewer

  // map_error transforms only Error. Identity makes the channel explicit here;
  // a real workflow can substitute a domain-specific error normalizer.
  let same_error = identity<AgentError>(str(id, ".same-error"))
  node_named(id, map_error(review_result, same_error))
}

let development_task = source("development-task", DevelopmentTask {
  prompt: "Implement and review the requested repository change."
})
let development = development_workflow("development", DevelopmentConfig {
  repository: ".",
  worktree: "tmp/mag-book-worktree",
  branch: "mag-book-work",
  base: "main",
  build: "cargo build"
})
let reviewed = development_task >>> development

// and_then binds Result-producing nodes: Error passes through unchanged and
// only Ok enters the continuation. choose branches over nominal Either and
// repacks it.
let decide = agents.agent<Review, Either<Approved, NeedChanges>>("decide", agents.AgentConfig {
  model: agents.standard,
  system: "Classify the review.",
  tools: general_tools,
  tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
  max_corrections: 2
})
let decided = and_then("decided", reviewed, decide)
let approved = identity<Approved>("approved")
let changes = identity<NeedChanges>("need-changes")
let branched = result_map(decided, choose("decision", approved, changes))

// Runtime cardinality is different from sequence's compile-time List. The
// planner's selected output is DynamicList<Followup>. traverse applies one
// ordinary typed worker node to every occurrence and preserves completion.
let planner = agents.agent<Either<Approved, NeedChanges>, DynamicList<Followup>>("planner", agents.AgentConfig {
  model: agents.standard,
  system: "Return ordered follow-up investigations.",
  tools: general_tools,
  tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
  max_corrections: 2
})
let planned = and_then("planned", branched, planner)

let followup_worker = agents.agent<Followup, Finding>("followup-worker", agents.AgentConfig {
  model: agents.standard,
  system: "Consume the typed Followup input, perform that investigation, and return its Finding.",
  tools: general_tools,
  tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
  max_corrections: 2
})
let workers = traverse("followups", followup_worker)
let workers_in_result = lift<DynamicList<Followup>, AgentError, DynamicList<Result<AgentError, Finding>>>("workers-result", workers)
let investigated = and_then("investigated", planned, workers_in_result)

// context activates once after explicit completion and supplies the ordered
// results to one integrating provider turn, including for an empty collection.
let result_context = context<Result<AgentError, Finding>>("followup-context")
let integrator = agents.agent<ProviderInput, FinalSummary>("integrator", agents.AgentConfig {
  model: agents.standard,
  system: "Integrate the ordered findings.",
  tools: general_tools,
  tool_approval_policy: named(ToolApprovalPolicy, Default, nil),
  max_corrections: 2
})
let integrate = result_context >>> integrator
let production = and_then("production", investigated, integrate)

// sequence shares Unit across fixed checks and preserves their order. before
// waits for those checks but retains the summary.
let build_check = script("verification.build", ShellScriptParams {script: "cargo build", cwd: ".", timeout: named(Timeout, Minutes, 2)})
let test_check = script("verification.test", ShellScriptParams {script: "cargo test", cwd: ".", timeout: named(Timeout, Minutes, 2)})
let fixed_checks = sequence([build_check, test_check])
let retain_summary = before("verification", identity<FinalSummary>("verification.summary"), fixed_checks)
let verified = result_map(production, retain_summary)

compile_graph(verified)
```

The compiled artifact uses `nefor.mag` version 4. Fixed combinators are
compile-time boundary and route transforms, not helper actors: `Unit`,
`Project`, `Pack`, `Unpack`, `Assemble`, and `EmptyList`. Their ordered steps
travel on routes and initial or template messages. Only capability actors have
runtime IDs, factories, firing, lifecycle, or logical membership.

An `Assemble` step names a destination-owned FIFO cohort by its structural path
and explicit slot. Equal-typed branches therefore remain distinct, including
when one producer feeds multiple slots; the destination consumes one value from
each slot in FIFO order. The same mechanism handles products and fixed lists.
`Node<Unit, T>` can be bootstrapped when its input boundary is exposed and
unfed, while a boundary behind an incoming route remains dependency-driven.
The result boundary observes transformed actor output directly: `result.from`
is a `StoredBoundary`, not a runtime result actor. Only explicit
`DynamicList` completion settles a dynamic terminal.

`Node<I, O>` is the reusable boundary. `left >>> right` feeds ordinary output
to input; `left *> right` runs a `Unit`-input node after the left and keeps the
right result; `left &&& right` sends one input to both branches and joins their
outputs. The related `***` operator maps two nodes over a product and `+++` maps
them over nominal `Either`. These are ordinary infix applications: keep
whitespace on both sides. Use prefix form such as `(>>>)(left, right)` only
when an expression needs the operator as an ordinary function value. Named
forms such as `before`, `node_named`, `choose`, and `sequence` also return
nodes and own explicit IDs where their contracts require one.

`sequence(nodes)` accepts a compile-time `List<Node<I, O>>`. Every child gets
the same `I`, and the output is an ordered `List<O>`. `DynamicList<T>` instead
records runtime-discovered indexed occurrences and explicit completion.
`traverse(id, worker)` lifts an ordinary `Node<I, O>` into a
`Node<DynamicList<I>, DynamicList<O>>`; `context<T>(id)` consumes the completed
ordered collection once. A traversal template contains capability actors only;
the intentional `traverse.result` result row is a real capability actor, not a
fixed-combinator placeholder.

Agents return `Result<AgentError, O>`. `result_map` transforms only `Ok`,
`map_error` transforms only `Error`, and `and_then(id, left, right)` chains two
Result-producing nodes. Deterministic nodes enter the same channel through
`lift<I, E, O>(id, node)`; `_` may fill inferable type holes.

Tool invocation authorization and human workflow approval are separate
surfaces. `named(ToolApprovalPolicy, Default, nil)` selects configured approval;
`named(ToolApprovalPolicy, Rules, ToolApprovalRules {rules: rules})` carries a
purpose-owned rule payload. The current runtime transports that metadata but
does not enforce it as a per-agent execution barrier. Human workflow approval
is owned by `nefor.human`: the facade's
`approval_gate`, `ApprovalConfig`, and `HumanWorkflowDecision` are the public
short names, replacing the former actor-owned gate and contracts-owned generic
decision.

Logical paths and runtime actor IDs are different identities. Actor IDs are
opaque strings: never split them on dots to infer hierarchy. `rename` changes
one displayed path segment, while `node_named` creates an expandable hierarchy
boundary. Every complete logical path must be unique within one run.
