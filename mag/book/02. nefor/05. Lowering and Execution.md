# Lowering and Execution

As MAG compiles an artifact, Nefor's graph libraries perform domain validation
before the actor runtime receives application data.

## Validation moves failures left

Node identity, typed boundaries, source/output shape, product coverage, runtime
contracts, reachability, and operation trigger outputs are checked during
construction and lowering. Typed captures and expression constructors retain
semantic descriptors while the closed operation schema prevents arbitrary code
from entering the artifact.

The implementation is in
[`nefor/graph.mag`](../../lib/nefor/graph.mag),
[`nefor/mag.mag`](../../lib/nefor/mag.mag), and
[`nefor/artifact.mag`](../../lib/nefor/artifact.mag).

## Graph validation errors

A program may type-check as MAG and still return an invalid topology.
`compile` and `compile_graph` validate the complete graph before any run starts;
a violation fails compilation with the library's message rather than starting a
broken run.

### Boundary structure

- A graph needs at least one edge.
- Only nodes whose complete input type is exactly `Unit` may have zero incoming
  edges. An ADT or product that merely contains `Unit` still requires an
  explicit input. The diagnostic starts with `root validation failed:` and names
  the node, its input boundary and type, and the reason.
- Exactly one output must exist. It needs an incoming edge and cannot source
  another edge.
- Every node must be reachable from a root whose input accepts `Unit`, and every
  node must have a path to the output.

Setting a role-like string on an ordinary node does not create root eligibility
or output authority: source and output roles require their concrete factory
shape, and ordinary nodes cannot carry initial messages. Use the public
constructors. Likewise, do not build low-level graph or boundary records by
copying fields; compiler-packed values cannot be forged with maps.

### Identity

One node id denotes one immutable definition. Reusing an id with different
configuration, ports, or behavior is an error even if duplicate edges would
otherwise collapse; give distinct nodes distinct ids, or reuse the exact same
node value. The diagnostic reports both definitions with their provenance, as
described under [Node boundary](<02. Graphs as Library Data.md#node-boundary>).
Runtime actor ids must also be unique across graph nodes, and logical node paths
must be non-empty and unique.

### Coverage

Input coverage: for input `(A, B)`, incoming routes must exactly cover every
occurrence. `(T, T)` needs two sender edges; one underfills it and three
overfill it. If the workflow means "either", declare a nominal ADT with one
constructor per alternative. If it means ordering only, use `Unit` as a product
component. The diagnostic starts with `input coverage failed:` and lists the
input boundary and expected type plus every incoming source and its type.

Output coverage: every actor output must be handled. Unless it reaches the
result boundary, each alternative of its type needs a compatible route or an
operation subscription; the diagnostic starts with `output coverage failed:`
and lists the available handlers.

A nominal ADT travels as its complete owner value. An agent's output is
`Result<AgentError, O>`, so a direct edge to an `O` input is incompatible: it
would erase the `Result` constructor. Connect the whole result, continue with
the Result combinators, or unpack and repack both constructors explicitly. A
route never erases an outer constructor merely because its payload type matches
the destination.

### Operations

Program operations must subscribe to a declared, non-result output with a
matching trigger type, and two operations with one id must be identical.

## Lowering

Applying `compile_graph` or the advanced `compile` transformation expands graph values.
Before root activation or product-input assignment, lowering forms one ordered
identity union across every stored occurrence. Compatible repeats are removed,
distinct routes and messages are retained, and identity conflicts stop
compilation with their pre-union provenance. Nodes carry that occurrence
provenance only while MAG composes and validates the graph; lowering erases it,
so program messages, logical nodes, and runtime envelopes are unchanged.
Performing this step before bootstrap and fan-in prevents reused source
boundaries from receiving extra activation and keeps product-position
assignment over the final route set.

After normalization:

- composite nodes contribute capability actors and routes;
- edges contribute routes between public boundaries, each with its ordered
  boundary transforms;
- initial messages and template messages retain their ordered transforms;
- every exposed, unfed node boundary whose input is exactly `Unit` contributes one
  topology-derived bootstrap message; incoming routes and explicit input
  messages suppress it, while nested actors stay dependency-driven;
- `Assemble` owns a destination-keyed FIFO cohort at its structural path and
  consumes one value from every explicit slot before emitting the product/list;
- ordered `InstantiateDeltaTemplate` operations contribute typed triggers,
  captures, the five expression forms, and actor-only structural templates; and
- the terminal node boundary becomes `result.from`, a `StoredBoundary` that
  observes transformed actor output without synthesizing an output actor.

Nefor emits an explicit `{format: "nefor.mag", version: 4}` envelope. Program
envelopes contain an initial concrete modification plus ordered operations;
delta envelopes contain one concrete delta and no result or nested operations.
Core MAG serializes this application value without knowing its schema.

A version-4 template has capability-actor slots, local and existing actor
references, typed actor routes with ordered transforms, transformed typed
messages, logical paths, scalar parameter bindings, and explicit
`actor_id`/`actor_id_list` relocation metadata. Fixed combinators are not
referenceable template entities. Its expression vocabulary is exactly `Trigger`,
`Capture`, `Field`, `IntToDecimalString`, and `ConcatStrings`. It has no source,
bytecode, generic AST, condition, cache directive, evaluator, post-compilation
function call, or generic construction expression.

Dynamic `Delta` values do not retain exposed node
boundaries, so their compatibility behavior is intentionally narrower: only an
unfed exact-`Unit` endpoint is bootstrapped. Feed other delta endpoints
explicitly rather than assuming completed-graph root activation applies.

## Execution

`mag.load` compiles and preflights an immutable program or delta envelope. It
returns the exact envelope and its content hash; it retains no compiler state.
`mag.execute` accepts only a program envelope and starts a fresh run.
`mag.apply` accepts only a delta envelope and atomically changes one live run.
Raw unversioned payloads and crossed envelope kinds are rejected.

The runtime preflights the complete operation list, registers capability actors,
installs transformed actor routes, delivers initial messages, invokes
capabilities, and routes outputs according to typed firing contracts. A
matching output queues its `InstantiateDeltaTemplate` operation. The kernel
evaluates the closed expression tree against that output, relocates the
actor-only template, validates the resulting delta against the live inventory,
and applies it atomically. Nested matching emissions join the same FIFO
operation queue; terminal success waits for that queue to become quiescent.

Version 4 deliberately provides no artifact cache, general runtime expression
language, or function application after compilation. The only runtime rows are
capability actors; a traversal's `traverse.result` row is intentional because
it is a real result capability, while fixed combinators never acquire rows.

## Runtime failures

A compiled graph can still fail while running. Failures that a library exposes
as typed values, such as `AgentError` or a nonzero process exit, are ordinary
data to route. A factory failure that no authored output carries, such as a
process timeout or a worktree capability error, escapes the typed model: the
run fails with `mag.run_failed`. A declarative operation whose materialization
is invalid or conflicts with the live run also fails the run, without applying
a partial delta. [Capability Nodes](<06. Capability Nodes.md>) lists which
outcomes each deterministic node routes.

## Diagnosing a failed workflow

1. Identify where the failure occurred: MAG language checking (a compiler
   diagnostic), graph validation (a library message during compilation),
   runtime execution, human approval, or run control.
2. Name the failed node, type, operation, or run from the diagnostic or run
   result.
3. Change the source or plan; do not resubmit the same artifact unchanged.
4. Compile and inspect the new preview.
5. Execute it as a fresh run and keep its new `run_id`.

Language-level diagnostics are described in the
[MAG compiler's error reference](../../../crates/nefor-mag/docs/errors.md). In
the lead workflow, `mag-apply` may also require an approved plan for a program
with write-capable agents, and that approval lasts only for the current turn;
see the [lead-workflow tools](../../../lua/libs/lead-workflow/README.md).

The runtime plugin documents the
[`IR`](../../../plugins/mag/docs/ir.md),
[`lowering`](../../../plugins/mag/docs/lowering.md), and
[`actor model`](../../../plugins/mag/docs/actor-model.md) in detail.
