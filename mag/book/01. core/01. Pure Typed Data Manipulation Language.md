# Pure Typed Data Manipulation Language

A MAG source file contains declarations and expressions. Evaluation is eager,
lexical, and pure: an expression produces a value without mutating an earlier
value or performing the work that value may describe.

Every entry program ends in an `Artifact`, which marks the value the compiler
returns:

```mag
type Greeting {message: String}
artifact(Greeting {message: "Hello from MAG"})
```

The argument can be any serializable MAG value. Compiling this program writes
that value verbatim as the successful result:

```json
{ "message": "Hello from MAG" }
```

MAG adds no fields or application schema to the artifact. Nothing interprets
the message during evaluation: the compiler verifies and serializes the value,
then stops.

## Bind intermediate values

`let` introduces one immutable name in its containing source-file or expression
block. Snake case is conventional for plain identifiers. Names containing
punctuation, spaces, or reserved words are enclosed in backticks.

```mag
type LanguageArtifact {language: String, numbers: List<Int>}
let language = "MAG"
let numbers = [1, 2, 3]
let double: fn(Int) -> Int = |value| => int_mul(value, 2)
let `=>`: fn(Int) -> String = |value| => str(value)
artifact(LanguageArtifact {language: language, numbers: numbers})
```

Here `` `=>` `` is simply the name of a function and `` `=>`(42) `` calls it.
Parentheses call a function with comma-separated arguments. Operators can also
be declared with a fixity and used infix; that surface still resolves to
ordinary function calls. Symbolic infix application always has whitespace on
both sides (`left + right`); delimiters do not substitute for whitespace. A
newline may follow an operator to continue its right operand, but an operator
cannot begin the next line. Alphabetic infix names remain valid as `1 add 2`,
and prefix operator calls such as `(=>)(42)` do not use the infix rule.

The four bindings above belong to one source-file block. `language`, `numbers`,
`double`, and `` `=>` `` remain available to every expression in that block.
The last expression is the block's result; in an entry program it must be an
`Artifact`. A function body follows the same rule, except its last expression
is the function's return value.

Bindings are immutable. Naming a value once and reusing it later does not create
an assignment channel or hidden state. All bindings in a block are peers: MAG
allocates the complete block before evaluating its initializers. Consequently a
value may refer forward to another value, and functions may recurse through a
chain of any length. For example, this strict value resolves `prefix` from a
later peer binding:

```mag
let message = str(prefix, " world")
let prefix = "hello"
```

Mutually recursive functions use the same peer visibility:

```mag
let finished = "done"
let first: fn(List<Int>) -> String = |items| => if (=)(count(items), 0) then finished else second(remove_at(items, 0))
let second: fn(List<Int>) -> String = |items| => if (=)(count(items), 0) then finished else first(remove_at(items, 0))
```

Recursion happens when a function is called, so ordinary call-depth and
evaluation-step limits bound it. Strict initializers, by contrast, must finish
while the block is being constructed. `let x = str(y, "!")` together with
`let y = str(x, "?")` is rejected as the initialization cycle `x -> y -> x`.
A cycle through a call is rejected too: a strict value cannot call a function
that immediately needs that still-initializing value.

## Values and collections

Ordinary strings interpret exactly `\n`, `\t`, `\\`, and `\"`. Triple-quoted
strings are raw and may span several lines. Scala-style `` `strip_margin` ``
lets source indentation remain readable without becoming part of the value:

```mag
let script = strip_margin("""|set -e
                                |echo 'export PATH="$HOME/.local/bin:$PATH"'
                                |find . \( -name '*.mag' -o -name '*.md' \)""")
let `one-line` = replace(script, "\n", " ")
```

The first value retains its line breaks; the second replaces them with spaces.
Triple-quoted strings perform no interpolation or escape processing.

```mag
import core.map.{}
import core.set.{}

type Values {unit: Unit, active: Bool, numbers: List<Int>}
type ValuesArtifact {values: Values, counts: Map<String, Int>, labels: Set<String>}
let values = Values {unit: nil, active: true, numbers: [1, 2, 3]}
let counts: Map<String, Int> = core.map.insert(core.map.empty<String, Int>(), "accepted", 2)
let labels: Set<String> = core.set.insert(core.set.empty<String>(), "ready")
artifact(ValuesArtifact {values: values, counts: counts, labels: labels})
```

A named constructor such as `Values {...}` creates its declared nominal record;
braced fields do not create an independent anonymous value. Bracket literals
create `List` values. Parentheses with commas create ordered tuples: `(1, "one")`
has type `(Int, String)`, while `(1,)` is the one-item tuple. A list, tuple,
or argument list may span several lines, and a comma after its last element is
optional. Native maps and
sets are unordered immutable data exposed by the ordinary `core.map` and
`core.set` modules; they have no literal syntax.

### Deriving new values

Nominal records and collections are transformed into new values.
`get` reads one field; `assoc` returns a value of the same record type with one
existing field replaced and leaves the original unchanged:

```mag
type Language {name: String, stable: Bool}
let language = Language {name: "MAG", stable: true}
let name = get(language, "name")
let renamed = assoc(language, "name", "Meta-Algebraic Grammar")
// name is "MAG"
// renamed is still Language and serializes as
// {"name":"Meta-Algebraic Grammar","stable":true}
```

The basic list operations inspect or reshape a list:

```mag
let numbers = [1, 2, 3]
let joined = concat(numbers, [4, 5])   // [1, 2, 3, 4, 5]
let size = count(numbers)              // 3
let head = first(numbers)              // 1
let shortened = remove_at(numbers, 1) // [1, 3]
```

Collection indices are known while MAG evaluates the program. Therefore
`` `remove_at`(numbers, 1000) `` fails compilation with an out-of-bounds
evaluation error rather than creating an invalid artifact.

Higher-order operations accept typed functions. Their result types follow from
the function signature:

```mag
let rendered = map(((|value| => str(value)): fn(Int) -> String), numbers)
let selected = filter(((|value| => (=)(value, 2)): fn(Int) -> Bool), numbers)
let repeated = flat_map(((|value| => [value, value]): fn(Int) -> List<Int>), numbers)
// rendered is ["1", "2", "3"]
// selected is [2]
// repeated is [1, 1, 2, 2, 3, 3]
```

`` `indexed_map` `` also provides each element's position:

```mag
type IndexedValue {index: Int, value: Int}
let indexed = indexed_map(
  ((|index, value| => IndexedValue {index: index, value: value}): fn(Int, Int) -> IndexedValue),
  numbers,
)
```

`fold` carries an explicitly typed accumulator, while `` `sort_by` `` derives a
key for every item:

```mag
let copied = fold(
  ((|out, value| => concat(out, [value])): fn(List<Int>, Int) -> List<Int>),
  ([]: List<Int>),
  numbers,
)
let ordered = sort_by(((|value| => str(value)): fn(Int) -> String), [3, 1, 2])
```

`` `group_by` `` derives one string key per item and accumulates duplicate keys
into ordered buckets. The callback runs from left to right and each bucket
retains source order. The resulting map is unordered: MAG exposes lookup and
membership, not key enumeration or a map fold.

```mag
import core.map.{}

type GroupedValue {group: String, value: Int}
let grouped = group_by(
  ((|item| => get(item, "group")): fn(GroupedValue) -> String),
  [
    GroupedValue {group: "b", value: 1},
    GroupedValue {group: "a", value: 2},
    GroupedValue {group: "b", value: 3},
  ],
)
let `b-values` = core.map.get(grouped, "b")
```

`core.map.insert` and `core.set.insert` reject an equal existing key or member
during eager evaluation. Map lookup and set membership use the same exact
structural equality as `(=)`. Map and Set equality is extensional and independent
of insertion order. No ordered Map/Set folds or enumeration functions are
exposed. Artifact serialization sorts entries canonically at the boundary; that
order is not observable to MAG code. String-keyed maps serialize as JSON objects;
other maps and sets use explicit `$mag` envelopes.

Equality is available only for concrete data: scalars, nominal records, ADTs,
lists, tuples, maps, sets, and recursively concrete contents.
Functions, `TypeTag`, `TypeDescriptor`, and other opaque behavioral/compiler
values are rejected statically rather than compared by runtime identity.

Integer arithmetic and ordering use explicit, general-purpose built-ins:

```mag
let doubled = int_mul(21, 2) // 42
let later = int_gt(8, 3)     // true
```

`` `int_mul` `` has type `fn(Int, Int) -> Int`. MAG integers are signed 64-bit
values, and multiplication that exceeds that range fails compilation during
eager evaluation instead of wrapping. `` `int_gt` `` has type
`fn(Int, Int) -> Bool` and performs strict greater-than comparison.

### Structural sharing

Compound values are structurally shared. Binding, passing, and storing the same
list, map, or typed value keeps a reference to immutable data instead of copying
the entire structure. This is an evaluator property, not a reference operation
visible to MAG code.

The complete [`01-values.mag`](../../examples/01-values.mag) program applies
these forms in one artifact.

## Compile without running

The standalone compiler prints the artifact itself as JSON:

```sh
mag compile 01-values.mag --source-dir .
```

```json
{ "record": { "...": "..." }, "copied": [1, 2, 3] }
```

A failed compilation writes a structured diagnostic to stderr, exits nonzero,
and produces no result on stdout. Neither the CLI nor the Rust API executes the
work described by the artifact.

## Root-local project builds

For repeated builds, put `mag.toml` in the project directory and use `mag build`:

```toml
version = 1
module-roots = ["lib", "/absolute/path/to/installed/nefor-mag/lib"]
```

An empty manifest is valid. Only `version` (defaults to 1) and `module-roots`
(defaults to empty) are accepted. The project directory itself is always the
first module root, followed by manifest roots and repeated `--module-root`
arguments in order. An installed include root contains the existing `core/` and
`nefor/` directories together; builds do not fetch packages or discover an
installation.

```sh
mag build main.mag --project ./project
mag build main.mag --project ./project --no-cache
```

`--project` defaults to the current directory. The manifest must be in that
exact directory: no upward discovery, named targets, or lockfile. Entry paths
are project-relative, as are relative module roots and `--input NAME=PATH`
paths. The four compiler-limit options and `--profile` also work with `build`.

Successful builds store the exact compact JSON plus final newline under
`.mag/cache/v1/`. Hits replay those bytes, without parsing or evaluating MAG.
Freshness checks reread consumed entry/module/text/JSON bytes and rerun the same
resolution queries, so unrelated edits remain hits and newly ambiguous modules
or JSON inputs invalidate. Complete host_input JSON, compiler limits, selected
paths, ordered roots and effective configuration partition requests. Manifest
comments and formatting do not. Compiler namespaces use the SHA-256 of the
actual executable bytes, not its version or filename; switching compiler or
source/context A -> B -> A retains A's records.

Cache records are inert local data, not authenticated artifacts. Missing,
corrupt, unsupported or stale records silently fall back to cold compilation.
Failures are never cached. Publication uses a complete temporary directory and
atomic rename after revalidating consumed inputs. Write failures do not fail a
successful build. This is not filesystem snapshot isolation: concurrent source
mutation can race a build, as it can with cold compilation. There is no
automatic eviction; `.mag/cache/` can be removed whenever desired. Executable
identity failures or non-UTF-8 request paths disable caching rather than
compilation.

`--no-cache` skips cache reads, executable hashing, observations and writes; it
never creates `.mag`. `mag compile` and `CompilerSession` also remain cold and
never access the project cache. Nefor runtime compilation does not adopt this
cache implicitly.

With `build --profile`, stderr contains the ordinary compile-profile fields plus
`cache`: `status` (`hit`, `miss`, `bypass`, or `unavailable`),
`lookup_duration_ns`, and `publication_duration_ns`. Lookup includes executable
hashing, identity construction, integrity checks and input validation;
publication is measured separately. A hit has zero compiler counters, phase
durations and compile `total_duration_ns`. That compile duration is not the
total build cost. Failed builds retain the ordinary fresh diagnostic and
optional failed-attempt compile profile. `compile --profile` keeps its existing
format.
